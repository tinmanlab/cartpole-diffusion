# Cart-Pole Diffusion

A beginner-first interactive lab for understanding **diffusion models and Diffusion Policy through Cart-Pole control**.

**Live site:** https://tinmanlab.github.io/cartpole-diffusion/

The project deliberately starts smaller than a full trained policy. The first goal is to make the mechanics visible:

```text
Cart-Pole state c
      ↓
clean future action chunk a0
      ↓  add Gaussian noise
noisy action chunk at
      ↓  iterative denoising conditioned on c
recovered action chunk
      ↓
execute a short prefix → observe again → replan
```

## Why Cart-Pole?

Image diffusion makes the core idea visually impressive but can hide the control interpretation. Cart-Pole gives every quantity a physical meaning:

```text
condition c = [cart position x, cart velocity x_dot,
               pole angle theta, pole angular velocity theta_dot]

action = continuous horizontal force
```

The browser lab lets you change the physical state, inspect a 16-step clean action chunk, add Gaussian noise with a diffusion-timestep slider, animate the reverse path, and execute the currently shown actions in Cart-Pole dynamics.

## v0.1 honesty contract

This page separates **real diffusion arithmetic** from the parts that are still pedagogical scaffolding.

| Part | v0.1 |
| --- | --- |
| Cart-Pole dynamics | computed in the browser |
| Clean action chunk | generated by a small hand-written teacher controller |
| Forward diffusion | real Gaussian corruption equation |
| Reverse visualization | oracle path that knows the true noise |
| Learned denoiser | **not implemented yet** |
| Vision input | **not implemented yet** |

The UI must never imply that the oracle reverse path is a trained Diffusion Policy.

## Core equation

Actions are normalized by the maximum force before diffusion:

```text
a_t = sqrt(alpha_bar_t) * a_0
    + sqrt(1 - alpha_bar_t) * epsilon

epsilon ~ Normal(0, I)
```

A real noise-prediction model learns approximately:

```text
epsilon_theta(a_t, t, condition) ≈ epsilon
```

A scheduler then uses the prediction to move from `a_t` toward a less noisy sample.

## Learning sequence

1. **Why diffusion?** Compare a direct state-to-action policy with iterative action-sequence generation.
2. **Forward diffusion.** Watch signal weight fall and noise weight rise.
3. **Reverse denoising.** Animate `t → 0` and see a coherent action sequence re-emerge.
4. **Conditioning.** Change `[x, x_dot, theta, theta_dot]` and watch the target action chunk change.
5. **Action chunking.** Execute only a prefix instead of the whole future sequence.
6. **Receding horizon.** Observe again and regenerate a new chunk.
7. **Real model boundary.** Identify exactly where a learned denoiser replaces the teaching oracle.

## Roadmap

### v0.2 — tiny learned state diffusion policy

- generate demonstration trajectories from a stronger teacher
- construct normalized state/action-chunk dataset
- train a tiny 1D denoiser
- export small weights for browser inference
- expose predicted noise beside true training noise
- compare oracle reverse path with learned reverse path

### v0.3 — multimodality

- construct states with multiple valid recovery trajectories
- visualize several samples from different noise seeds
- compare deterministic regression vs diffusion samples

### v0.4 — vision

- render Cart-Pole frames
- condition on image/frame history instead of privileged simulator state
- show visual encoder features separately from the denoiser

### Later

State + vision fusion, noisy/missing sensors, longer temporal context, transformer denoisers, DDPM/DDIM scheduler comparison, and links to manipulation-style Diffusion Policy examples.
