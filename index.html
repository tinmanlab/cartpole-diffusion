Heatmap을 왜 쓰나요?
각 세로 셀 하나는 16-step action chunk의 같은 index입니다. 위쪽 ladder에서 아무 셀이나 가리키면 모든 timestep의 같은 column이 동시에 강조됩니다. 그래서 “action[7]이 noise에서 어떻게 안정되는지”를 시간축으로 추적할 수 있습니다. 이 linked-hover 방식은 Polo Club Transformer Explainer의 MatrixSvg가 row/column을 강조하고 나머지를 dim 처리하는 패턴을 Diffusion action vector에 맞게 단순화한 것입니다.
Learned εθ와 Oracle ε
Learned εθ는 실제 6,000-step 학습 MLP가 noise를 예측합니다. Oracle ε는 forward 과정에서 사용한 진짜 noise를 알고 있어서 이상적인 기준입니다. 같은 start latent에서 둘을 비교하면 diffusion algorithm 자체와 model error를 분리할 수 있습니다. Pure-noise generation은 Learned에서만 가능합니다.
왜 Cart-Pole인가?
Diffusion 자체를 설명하기 위해 action이 16개의 숫자로 짧고 눈에 보이는 문제를 택했습니다. 여기서 중요한 것은 Cart-Pole 성능이 아니라 condition + noisy sequence + iterative denoising 구조입니다.
