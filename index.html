왜 이렇게 구성했나?
왼쪽은 환경입니다. 50 Hz로 계속 움직이고, Diffusion policy는 현재 상태 c=[x,ẋ,θ,θ̇]를 조건으로 16개의 미래 force를 생성합니다. 그중 앞 4개만 실행한 뒤 새 상태에서 다시 Gaussian noise부터 plan을 만듭니다. 오른쪽은 최신 plan에서 모델이 실제 계산한 aₜ, εθ, 추정 a₀, 다음 latent를 보여줄 뿐이며 제어 계산을 다시 구현하지 않습니다.
Forward diffusion은 어디 갔나?
실제 실행 시에는 Gaussian noise에서 시작해 reverse diffusion만 사용합니다. Forward diffusion aₜ = √ᾱₜ a₀ + √(1−ᾱₜ)ε 은 학습할 때 clean demonstration에 known noise를 섞어 εθ의 정답을 만드는 과정입니다. 실행 화면에서 forward 과정을 항상 보여주면 “정답 action을 알고 생성한다”는 오해가 생길 수 있어 아래 설명으로 내렸습니다.
Transformer 버전과 같은 설계 원칙
cartpole-transformer도 Environment → Model → Explainer를 분리합니다. 50 Hz simulation이 history를 만들고, learned Transformer가 실제 intermediate tensor를 내며, explainer가 그것을 시각화합니다. 여기서는 history token 대신 최신 Diffusion action plan과 denoising history를 시각화합니다. 화면도 가로에서는 좁은 simulation + 넓은 explainer, 세로에서는 위 simulation + 아래 explainer로 자동 전환합니다.
범위
현재 모델은 upright 근방 Cart-Pole demonstration으로 학습한 작은 교육용 denoiser입니다. 목적은 Diffusion의 iterative denoising을 이해하는 것이며, Cart-Pole SOTA나 manipulation-scale Diffusion Policy 성능을 주장하지 않습니다.
